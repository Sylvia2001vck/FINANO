Executive Summary FINANO is a full-stack, fintech-oriented web application. Built as a Single Page Application (SPA) using React, TypeScript, and Vite with Ant Design, it is powered by a robust backend utilizing FastAPI, SQLAlchemy 2.0, and JWT authentication. The platform focuses on portfolio tracking, financial notes, community engagement, and innovative AI features: FBTI (Finance MBTI) profiling and a MAFB (Multi-Agent Finance Board). The MAFB utilizes a LangGraph pipeline encompassing RAG, compliance checks, and market similarity analytics to assist in fund selection. Status: Core user flows, the MAFB console, FBTI assessment, fund cataloging (with OCR-assisted input), and Docker deployment configurations are fully implemented and demo-ready. Remaining tasks will focus on performance hardening, expanding automated test coverage, and public hosting. 3. Completed Work Authentication & User Profile: Secure registration/login with JWT storage (Zustand) and protected routes. User profiles track key metrics (MBTI, birth date, risk tolerance) to power MAFB/FBTI pipelines. Core Pages: Dashboard, trade logs, notes, AI analytics page, and community forum (posts/likes). FBTI Engine: Integrated an 8-question assessment flow yielding 16 financial archetypes, persistently stored via API, paired with dedicated result and AI fund-picking views. MAFB Pipeline: Deployed a LangGraph (0.2.x) multi-agent workflow: Profiling → Parallel Analysts (Fundamental/Technical/Risk/K-line) → Allocation → Compliance → Final Report. Integrated Server-Sent Events (SSE) for real-time UI stage tracking. Data Integration & Similarity: Implemented dual catalog modes ( static vs. eastmoney_full ), EasyOCR for fund code extraction, and optimized cosine/K-line similarity algorithms with throttling, caching, and candidate pre-filtering to minimize latency. 4 . Core Technical Focus: MAFB & AI Integration Both the MAFB evaluation and FBTI AI stock selection leverage a unified financial LLM adapter ( backend/app/agent/llm_client.py ). Adapter & Routing: Injects a "licensed, compliant, non-predictive" system prompt. Uses an auto-fallback chain: DashScope → DeepSeek → Ollama → Local Qwen-1.8B. Structured Output (JSON): Forces strictly validated JSON outputs via Pydantic ( AgentScore / ComplianceLLMResult ). Parse failures trigger deterministic rule-based fallbacks (e.g., Sharpe/momentum scoring). Three-Stage FBTI Process: 1. Preference Structuring: Converts user tags (FBTI, Five Elements) into a JSON profile. 2. Candidate Narrowing: Reduces the pool to Top 20 via weighted scoring (No LLM). 3. Final Selection: Analyzes the thinned Top 20 array with the LLM to output a compliant JSON array of up to 5 funds with justifications. Major Challenges & Mitigations Slow LLM Responses blocking MAFB: Mitigated by wrapping agent scoring calls in a strict timeout ( MAFB_AGENT_LLM_TIMEOUT_SEC ).
